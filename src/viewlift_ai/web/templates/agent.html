Debug with an AI agent

Viewlift AI runs an MCP server next to this console. A coding agent such as Cursor calls its tools to read traffic, logs, and live state from a debug build, and to change that build when you allow it. Every call names one app, so two apps on the same phone never get mixed up.

How it works

The agent never talks to the phone. It calls the MCP server, which calls this console on loopback. The console queues a command for one app. That app's capture SDK picks it up within half a second, runs it, and posts the result back. The MCP tool waits for that result and returns it to the agent.

Connect Cursor

  1. Start the console and the MCP server together.

    scripts/viewlift-ai.sh start

    Ctrl+C stops both. stop, restart, and status cover both processes.

  2. Add the server to ~/.cursor/mcp.json or the project's .cursor/mcp.json.

    {
  "mcpServers": {
    "viewlift-ai": {
      "url": "{{ mcp.url }}"
    }
  }
}

  3. Open Cursor Settings, then MCP, and turn on viewlift-ai. The server has {{ tool_count }} tools. A chat starts with the debug set. manage_workflows turns on project, targets, simulator, UI, device, macOS, LLDB, SwiftPM, coverage, docs, or previews for that chat, and disabling the group drops those schemas back out. VIEWLIFT_AI_MCP_WORKFLOWS sets the starting set.

  4. Run a debug build that links ViewliftNetworkCapture. Then ask the agent about it in plain words.

Run without the script (stdio)

Cursor starts the server itself. The console still has to be running.

{
  "mcpServers": {
    "viewlift-ai": {
      "command": "uv",
      "args": ["run", "--extra", "mcp", "--directory", "/path/to/Viewlift_AI", "viewlift-ai-mcp"],
      "env": { "VIEWLIFT_AI_URL": "{{ console_url }}" }
    }
  }
}

A first session

An example with sample data: what the agent does for one bug report. You only write the first line.

  1. You

    Alpha on my iPhone 16 simulator shows an empty home screen. Find out why.

  2. Agent list_apps(online_only=true) 
    Alpha  com.viewlift.alpha  app-a  iPhone 16  online
Beta   com.viewlift.beta   app-b  iPhone 16  online
  3. Agent list_flows(client_id="app-a", status=401) 
    GET  api.viewlift.com/content/pages?path=/home  401  182 ms
  4. Agent app_inspect(client_id="app-a", command="ott.snapshot") 
    user.isLoggedIn: true
user.tokenExpiry: 2026-11-05T14:02:11Z   (expired)
  5. Agent list_logs(client_id="app-a", level="error") 
    AuthService: refresh skipped, refreshToken is nil
  6. Agent

    The home page request returns 401 because the access token expired and the refresh never ran. AuthService skips refresh when refreshToken is nil, and the app still reports the user as logged in. Beta was not touched.

Many apps, one device

Each install gets its own client_id. Apps on the same simulator or phone share a device_key. The agent must pass a client_id, or a bundle id that matches exactly one online app. With no id, or an ambiguous one, the tool returns the list and does nothing.

Guardrails

  • Loopback only. The MCP server and the console accept connections from this Mac only.
  • One app per call. The server never falls back to the most recent app.
  • Writes need confirm. Without confirm: true, a write tool returns before it sends anything.
  • Redacted by default. Tokens and secrets in flows stay masked. Raw bodies and replay need reveal already unlocked in the console. No tool unlocks it.
  • Keychain values never leave. Keychain reads return item metadata only.
  • Network profile. A profile shapes the selected app through the SDK. It needs that app and confirm.

Prompts to try

  • Which apps are connected right now, and on which devices?
  • Show the failed requests from Beta in the last few minutes and explain each one.
  • Take a screenshot of Alpha and run an accessibility audit on that screen.
  • Alpha froze when I opened the player. List its hangs and point me to the code.
  • Turn on the newPlayer flag in Alpha only, then tell me what changed in its requests.
  • Set the network to 3G and check whether Alpha still loads the home page.
  • Compare the OTT snapshot of Alpha and Beta. Why does only one show the TVE login?

Troubleshooting

Cursor shows no tools
The MCP server is not running. Run scripts/viewlift-ai.sh status, then restart. Its log is .viewlift-ai-mcp.log.
Tools return "console is not reachable"
The console is stopped or on another port. Start it, or set VIEWLIFT_AI_URL for the MCP server.
"client_id is required" or a list of apps
The agent did not name one app. Tell it which app, or ask it to call list_apps first.
"debug command timed out"
The app is in the background, paused in the debugger, or offline. Bring it to the front and retry.
"module disabled" in the result
That module is not in the app's debugModules. Add it to the capture configuration and rebuild.
